# Модель и её запуск на сервере с RTX 5090 (32 ГБ)

Назначение: один рабочий на одной карте пишет код и реализует алгоритмы под управлением
`hermes-harness`. Приоритет — правильность результата; скорость берём только там, где она
ничего не стоит по качеству.

## 0. Исполнителю: что считается сделанным и чего не делать

Этот документ отдаётся агенту, который поднимает сервер. Границы:

- **Сначала выясни, потом меняй.** Как сейчас запущен `llama-server` (команда, пользователь, systemd/nohup/скрипт),
  где лежит текущий GGUF, сколько свободно на диске (нужно ≥ 25 ГБ), версии `nvidia-smi`, драйвера и CUDA
  toolkit в WSL2, версия/коммит текущей сборки llama.cpp. Запиши это в отчёт до первого изменения.
- **Не останавливай сервер, пока идёт задача харнесса.** Признак: живой `run.sh`/`review.sh` или
  `hermes` в `ps`, либо файл `<проект>/.hermes-harness/run.lock` с живым pid. Дождись конца.
- **Старая модель и старая сборка остаются на месте** до приёмки. Новый сервер поднимай на другом
  порту (например 8081), гони проверки там, и только потом переключай 8080.
- **Драйвер не трогай без отдельного подтверждения человека.** Если проверка 5 указывает на откат — доложи и остановись.
- Ничего не ставить через `sudo`, кроме того, что прямо названо в разделе 2; никаких правок в `~/.hermes/`
  и в репозиториях проекта — это делает другой документ и другой исполнитель.

«Сделано» означает одновременно:

1. `curl /v1/models` отдаёт имя модели, и оно записано в отчёт.
2. Проверка `tool_calls`: `tool_calls: True`, `reasoning separated: True`.
3. Из журнала сервера в отчёте: строка про размер KV-кэша при `-c 131072`, занятая память по `nvidia-smi`
   под нагрузкой, tok/s на ответе длиннее 500 токенов **с MTP и без него** (два запуска), доля принятых черновиков.
4. Один запрос на ~2000 токенов кода (например «напиши класс LRU-кэша с тестами на pytest») дописан до конца,
   не обрезан.
5. Версия драйвера в отчёте; если она 591.86 или новее — отдельной строкой предупреждение об обрыве после ~70k.

Отчёт — один файл `serving-report.md` рядом с этим документом: что было, что стало, все числа из пунктов 1–5,
точная команда запуска, которая работает, и как её перезапускать после перезагрузки. Числа, а не слова:
«быстро» и «работает» не принимаются.

## 1. Решение

| Что | Выбор | Почему |
| --- | --- | --- |
| Модель | `Qwen/Qwen3.8-27B`, официальная | В ярусе 24–32 ГБ сильнейшая измеренная: SWE-bench Pro 61,7, Terminal Bench 2.1 73,0, LiveCodeBench v6 90,3. Плотная, 262k контекста, Apache 2.0 |
| Сборка | GGUF от `unsloth/Qwen3.8-27B-GGUF`, квант **Q6_K** (22 ГБ) | Квант от BF16, а не от Q8; несёт тензоры MTP-головы. Q6_K — верх того, что помещается вместе с кэшем |
| Движок | llama.cpp (`llama-server`), сборка не старее июля 2026 | Уже проверен на этом сервере с родными `tool_calls`; поддерживает MTP для этой модели. vLLM/SGLang с NVFP4 быстрее, но NVFP4 — 4-битный квант, это плата качеством |
| Контекст | `-c 131072`, KV в q8_0 | Q6_K + 131k кэша ≈ 27–28 ГБ, помещается с запасом. 262k при Q6_K не влезает; при Q5_K_M влезает, но Hermes сжимает историю раньше, чем она туда дорастёт |
| Размышление | включено | Агентные замеры Qwen сделаны с ним; наша наблюдённая беда — небрежность, а не медлительность |

Чего не делать: сборки с абляцией («uncensored», «cyber» и т. п.). Для кода они не покупают
ничего, а их влияние на надёжность вызова инструментов никем не измерено — перплексия
про это молчит. Квант, снятый с Q8, а не с BF16, — вторая ненужная потеря.

## 2. Откуда брать

Файл выбирается по метке кванта, имя угадывать не надо:

```bash
# сборка llama.cpp (нужен CUDA toolkit под драйвер; Blackwell = sm_120)
git clone https://github.com/ggml-org/llama.cpp && cd llama.cpp
cmake -B build -DGGML_CUDA=ON -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release -j
ldd build/bin/libggml-cuda.so* | grep cudart      # заголовки и библиотека CUDA одной мажорной версии

# модель: -hf скачает и закэширует сам (~22 ГБ)
./build/bin/llama-server -hf unsloth/Qwen3.8-27B-GGUF:Q6_K --help >/dev/null
```

Если хочется держать файл руками:

```bash
pip install -U "huggingface_hub[cli]"
hf download unsloth/Qwen3.8-27B-GGUF --include "*Q6_K*" --local-dir /models/qwen3.8-27b
# в старых установках команда называется huggingface-cli download, ключи те же
```

## 3. Запуск

```bash
llama-server \
  -hf unsloth/Qwen3.8-27B-GGUF:Q6_K \
  -c 131072 -ctk q8_0 -ctv q8_0 -fa on -ngl 99 \
  -b 4096 -ub 1024 \
  --parallel 1 --cache-reuse 256 \
  --spec-type draft-mtp --spec-draft-n-max 2 \
  --jinja --reasoning-format deepseek \
  --chat-template-kwargs '{"enable_thinking":true}' \
  --temp 1.0 --top-p 0.95 --top-k 20 --min-p 0.0 \
  --repeat-penalty 1.0 --presence-penalty 0.0 \
  --host 127.0.0.1 --port 8080
```

По строкам:

- `-c 131072` — окно; то же число обязано стоять в `model.context_length` харнесса.
- `-ctk/-ctv q8_0 -fa on` — кэш вдвое дешевле почти без потерь; квантованный V-кэш требует flash attention.
- `-b 4096 -ub 1024` — быстрее предзаполн длинных запросов (агент шлёт весь разговор каждым ходом).
- `--parallel 1` — одна ячейка; требуется для MTP, и второй одновременный запрос нам не нужен.
- `--cache-reuse 256` — переиспользование KV-префикса между ходами, иначе предзаполн каждый раз с нуля.
- `--spec-type draft-mtp --spec-draft-n-max 2` — MTP-голова из самого GGUF. Ускорение без изменения выхода.
- `--jinja` — без него нет родных `tool_calls`; Hermes не разбирает вызовы из текста и молча их отбрасывает.
- `--reasoning-format deepseek` — размышление уходит в `reasoning_content`, а не в текст ответа.
- Выборка — по карточке Qwen для режима размышления. Умолчания сервера (`top_k 40`, `min_p 0.05`) с ней расходятся. Жадный выбор (`--temp 0`) запрещён карточкой: зацикливание.
- `max_tokens` не задаём ни здесь, ни в Hermes: длинный файл кода должен дописываться до конца.

Единственное сравнение, которое стоит провести: `--temp 0.6` против `1.0` на одной и той же
задаче. Меньше — стабильнее JSON вызовов и дословность кода; больше — по карточке.

## 4. Проверка после запуска — все пять, каждый раз после смены модели

```bash
# 1. сервер видит модель; это имя идёт в model.default
curl -s http://127.0.0.1:8080/v1/models | python3 -m json.tool

# 2. родные tool_calls (Hermes без них бесполезен)
curl -s http://127.0.0.1:8080/v1/chat/completions -H 'Content-Type: application/json' -d '{
  "model":"x","messages":[{"role":"user","content":"What is the weather in Paris? Use the tool."}],
  "tools":[{"type":"function","function":{"name":"get_weather","parameters":{"type":"object",
  "properties":{"city":{"type":"string"}},"required":["city"]}}}]}' \
  | python3 -c "import json,sys; m=json.load(sys.stdin)['choices'][0]['message']; print('tool_calls:', bool(m.get('tool_calls'))); print('reasoning separated:', 'reasoning_content' in m)"
# ожидаем: tool_calls: True, reasoning separated: True

# 3. память: строка вида 'KV self size' в журнале сервера — сколько занял кэш при -c 131072
# 4. скорость: в журнале сервера на длинном ответе — tok/s и доля принятых черновиков MTP (ждём 0,7–0,8)
# 5. драйвер
nvidia-smi --query-gpu=driver_version --format=csv,noheader
```

Про пункт 5. Известен обрыв скорости декодирования Qwen3.8 в llama.cpp примерно в 25 раз после
~70–80k токенов контекста. Он драйверный: воспроизводится на 591.86 и новее, на 5090 с ветки
580.x — нет. Если после ~70k tok/s падает с десятков до единиц — откатить драйвер на 580.x,
а не искать причину в харнессе.

## 5. Что даёт ускорение и чем оно платит

| Рычаг | Скорость | Цена качеством | Решение |
| --- | --- | --- | --- |
| MTP-голова | +33–39 % декодирования | нет — распределение выхода не меняется | включить |
| KV q8_0 | вдвое меньше памяти | пренебрежимо | включить |
| KV q4_0 | вчетверо меньше памяти | заметная на длинном контексте | нет |
| Квант Q5_K_M вместо Q6_K | чуть быстрее, влезает 262k | небольшая, но есть | нет, пока Q6_K помещается |
| NVFP4 на vLLM/SGLang | до 200+ tok/s на 5090 | 4-битный квант весов | нет; вернуться, если время станет главным ограничением |
| Выключить размышление | заметно | падение на многошаговых задачах | нет |

## 6. Смена модели без остановки харнесса

1. Остановить обе петли (`run.sh`, `review.sh`) — дождаться конца текущей задачи, они не прерывают её посередине.
2. Перезапустить `llama-server` по разделу 3, пройти раздел 4.
3. `hermes config set model.default '<имя из /v1/models>'` и `hermes config set model.context_length 131072`
   (или `./install.sh`, если эти значения уже в `config.yaml` харнесса).
4. `hermes hooks doctor` и `./selftest.sh ~/.hermes` — оба должны быть чистыми.
5. Один прогон одной задачи с `HH_MAX_TASKS=1`, глазами, прежде чем отпускать очередь.
